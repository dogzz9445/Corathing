# Corathing 주요 요소 정리

이 문서는 Corathing 프로젝트의 핵심 추상화, 디렉터리 역할, 플러그인(위젯/데이터소스) 카탈로그를 정리한 참고 자료입니다. [CLAUDE.md](../../CLAUDE.md) 가 "어떻게 일할지" 를 알려준다면, 이 문서는 "무엇이 어디에 있는지" 를 알려주는 목차입니다.

## 2. 핵심 도메인 모델 (Contracts/Bases)

| 클래스 | 경로 | 설명 |
|---|---|---|
| `ProjectState` / `ProjectCoreState` | [src/Shared/Corathing.Contracts/Bases](../../src/Shared/Corathing.Contracts/Bases/) | 프로젝트 이름, 선택된 워크플로우 ID, 워크플로우 리스트 |
| `WorkflowState` / `WorkflowCoreState` | 〃 | 워크플로우 이름, 최대 컬럼(16), 표시 행(8), 포함 위젯 ID |
| `WidgetState` / `WidgetCoreState` | 〃 | 위젯 TypeName, 레이아웃(row/col/span), 타이틀, 배경색, CustomSettings(object) |
| `DataSourceState` / `DataSourceCoreState` | 〃 | TypeName, 타이틀, 위젯 의존 플래그, CustomSettings |
| `PackageState` / `PackageReferenceState` | 〃 | 어셈블리 이름/버전, 패키지 ID, 설명 |
| `WidgetLayout` / `WidgetLayoutRect` | 〃 | 그리드 좌표/크기 |
| `WidgetContext` (abstract) | [WidgetContext.cs](../../src/Shared/Corathing.Contracts/Bases/WidgetContext.cs) | 모든 위젯의 MVVM 베이스. 수명주기 훅: `OnCreate`, `ApplyState`, `OnStateChanged`, `OnResized`, `SaveState`, `Destroy` |
| `DataSourceContext` (abstract) | 〃 | 모든 데이터소스 MVVM 베이스. 훅: `OnCreate`, `ApplyState`, `OnStateChanged`, `OnMessage` (예정) |
| `CustomSettingsContext` (abstract) | 〃 | 위젯/데이터소스 옵션 뷰↔DTO 양방향 동기화 |

### 설정(Configurations) 최상위 컨테이너

- `AppSettings` — 앱 전체 설정 (테마 선택, 언어, 인증, 저장소 경로)
- `AppPreferenceState` — 사용자 환경설정
- `AppPackageState` — 로드된 패키지 레지스트리
- `AppDashboardState` — 전체 Project/Workflow/Widget/DataSource 트리 + 캐시 맵

## 3. 플러그인 속성(Attribute) — 리플렉션 등록 메커니즘

[src/Shared/Corathing.Contracts/Attributes](../../src/Shared/Corathing.Contracts/Attributes/):

| 속성 | 대상 | 역할 |
|---|---|---|
| `[EntryCoraWidget]` | `WidgetContext` 파생 클래스 | 위젯 메타데이터 (contextType, customSettingsType, customSettingsContextType, name, description, menuPath/Order/Tooltip, 레이아웃 제약) |
| `[EntryCoraWidgetName(lang, str)]` | 〃 | 언어별 표시 이름 |
| `[EntryCoraWidgetDescription(lang, str)]` | 〃 | 언어별 설명 |
| `[EntryCoraWidgetDefaultTitle(lang, str)]` | 〃 | 언어별 기본 타이틀 |
| `[EntryCoraDataSource]` | `DataSourceContext` 파생 클래스 | 데이터소스 메타데이터 (dataSourceType, optionType, settingsContextType, name, description, defaultTitle) |
| `[EntryCoraDataSourceName/Description]` | 〃 | 언어별 메타 |
| `[AssemblyCoraPackageName]` | 어셈블리 | 패키지 표시 이름 |
| `[AssemblyCoraPackageDescription]` | 〃 | 패키지 설명 |
| `[AssemblyCoraPackageDataTemplate]` | 〃 | 패키지의 XAML DataTemplate 리소스 URI |
| `[AssemblyCoraPackageResourceManager]` | 〃 | 로컬라이즈용 `ResourceManager` 타입 |
| `[ReferenceCoraDataSourceProperty]` | 위젯 옵션 프로퍼티 | 해당 프로퍼티가 DataSource 참조임을 선언 |

`PackageService.LoadDLL` 이 `Assembly.LoadFrom()` → 모든 타입 스캔 → 위 속성 추출 → `CoraWidgetInfo`, `CoraDataSourceInfo`, `CoraPackageInfo` 로 변환해서 딕셔너리에 등록합니다.

## 7. 메시징 (MVVM Messenger)

`WeakReferenceMessenger.Default.Send(...)` 로 전역 이벤트 브로드캐스트. 메시지 타입은 [Contracts/Messages/](../../src/Shared/Corathing.Contracts/Messages/):

- `CustomSettingsChangedMessage` — 위젯/데이터소스 설정 변경
- `DataSourceStateChangedMessage` — DataSource 추가/제거
- `EntityStateChangedMessage` — 엔터티 범용 변경
- `WidgetStateChangedMessage` — 위젯 추가/제거/업데이트
- `PackageStateChangedMessage` — 패키지 로드/언로드

## 12. CI / 빌드 파이프라인

- [.github/workflows/ci.yml](../../.github/workflows/ci.yml) — `main`, `maintenance/*`, PR 트리거. `dotnet-version: 10.0.x` → `dotnet restore` → `dotnet build Debug` → `dotnet publish Release (framework-dependent)` → `actions/upload-artifact@v4` 로 아티팩트 업로드.
- [.github/workflows/cd.yml](../../.github/workflows/cd.yml) — git tag 푸시 시 `dotnet publish --self-contained true -r win-x64` → `Compress-Archive` → `softprops/action-gh-release@v2` 로 GitHub Release 생성.
- 버전 관리: [version.json](../../version.json) — Nerdbank.GitVersioning (`nbgv`). 두 워크플로우 모두 `fetch-depth: 0` 필수.
