## 2. .NET 10 마이그레이션 + 빌드 함정 제거

문서화하면서 발견한 "쌓여 있던 문제들" 일괄 정리.

### 2.1 Avalonia 레거시 제거

쓸 계획 없는데 곳곳에 흔적이 남아 있었음.

- `src/Apps/Directory.Build.props`, `src/Shared/Directory.Build.props` — `<AvaloniaVersion>` 제거
- [src/Shared/Corathing.Dashboards/Controls/IDashboardHost.cs](../../src/Shared/Corathing.Dashboards/Controls/IDashboardHost.cs) — TODO 주석 삭제
- README.md, CLAUDE.md, docs/memory/주요요소.md, docs/todo.md 내 모든 언급 제거

### 2.2 위젯 DLL 참조 HintPath

[Corathing.Organizer.WPF.csproj](../../src/Apps/Corathing.Organizer.WPF/Corathing.Organizer.WPF.csproj) 가 Widgets.Basics 를 `ProjectReference` 가 아닌 **DLL `<Reference>`** 로 가져가는 의도된 구조인데, HintPath 가 `net8.0-windows` 로 박혀 있어서 net10 빌드 후 참조가 깨지고 있었음.

- HintPath 에 `$(Configuration)` MSBuild 변수 도입 → Debug/Release 모두에서 경로 해결
- `net8.0-windows` → `net10.0-windows10.0.19041.0` 로 일치
- CLAUDE.md 에 "DLL 참조는 플러그인 구조라서 의도된 것" 이라고 명시 (다음에 누가 봐도 ProjectReference 로 고치려 들지 않도록)

### 2.3 Localization Designer.cs 관습 제거 ⭐

**가장 큰 수확.** 기존에는 `.resx` 수정 → `*.Designer.cs` 자동 재생성 → `git update-index --assume-unchanged` 로 diff 숨기기 라는 지저분한 관습이 있었음.

실제 사용처를 grep 해보니 `.ResourceManager` 속성만 쓰고 있어서, 10줄짜리 수동 wrapper 로 완전히 대체 가능했음.

- [BasicWidgetStringResources.cs](../../src/Widgets/Corathing.Widgets.Basics/Resources/BasicWidgetStringResources.cs) 신규 — 수동 wrapper
- [CorathingOrganizerLocalizationStringResources.cs](../../src/Apps/Corathing.Organizer.WPF/Resources/CorathingOrganizerLocalizationStringResources.cs) 신규 — 수동 wrapper
- 대응 `*.Designer.cs` 파일 삭제
- `.csproj` 에서 `Generator` / `LastGenOutput` 메타데이터 제거
- CONTRIBUTE.md 재작성 — `--assume-unchanged` 관습 제거, `.resx` 만 편집하면 된다고 명시

회고 포인트: "돌아는 가는데 찜찜한 관습" 이 1년쯤 쌓여 있었는데, 실제로 뭘 쓰는지 확인하니 5분 작업이었다. 다음에 비슷한 것 발견하면 먼저 grep 부터.

### 2.4 CI/CD 단순화

[.github/workflows/ci.yml](../../.github/workflows/ci.yml), [cd.yml](../../.github/workflows/cd.yml) 전면 재작성.

- `dotnet-version: 8.0.x` → `10.0.x`
- CI 가 참조하던 `Corathing.Organizer.WPF.UnitTests`, `Corathing.Package` (.wapproj) — 존재하지 않는 프로젝트라 제거
- CD 의 5채널 매트릭스(Dev/DevExe/ProdExe/Prod_Sideload/Prod_Store) → 단일 self-contained zip + GitHub Release
- `softprops/action-gh-release@v2` 로 릴리스 노트 자동 생성

회고 포인트: MSIX/WAP 은 언젠가 필요하면 별도 워크플로우로 붙이는 게 낫겠음. 현재 스케일에서는 self-contained zip 이 충분.
